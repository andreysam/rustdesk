# Сборка «Новодок remote» с индивидуальными паролями

`RUSTDESK_SERVER_URL` задаёт домен RustDesk-сервера при сборке. Адрес регистрации
вычисляется из этого домена, HTTPS-порт 443 и путь **`/credentials/v1/devices/enroll`**
закреплены в коде. Например, `rd.example.org:21116` даёт
`https://rd.example.org/credentials/v1/devices/enroll`.

Ранее использовавшиеся `RUSTDESK_CLIENT_PASSWORD` и `RUSTDESK_CLIENT_PASSWORD_SALT`
больше не используются. Общего встроенного пароля и резервного входа нет.
Настройка `RUSTDESK_SERVER_API` относится к штатному API RustDesk и не задаёт адрес
нового сервиса учётных данных.

Backend — отдельный проект `../rustdesk-backend`. До распространения новой сборки
разверните его с собственной SQLite-базой, доступом только на чтение к каталогу
hbbs и доверенным HTTPS-сертификатом.

При первом запуске серверной части клиент генерирует индивидуальный пароль,
подписывает регистрацию существующим ключом RustDesk и отправляет её backend.
Backend сверяет ключ с `peer.pk` в базе hbbs; если hbbs ещё не зарегистрировал ID,
клиент повторит попытку через 30 секунд. Требуется синхронизация часов (±5 минут).

Backend сохраняет пароль в зашифрованном виде и возвращает его клиенту. Только
после этого клиент сохраняет штатный зашифрованный хеш и локальную привязку к ID,
ключу, домену и хешу. Открытый пароль на диске клиента не сохраняется. Такой порядок
не оставляет устройство с неизвестным backend паролем при сетевом сбое. Если процесс
завершился между отправкой и сохранением, повторный подписанный запрос вернёт тот
же пароль; новый кандидат не перезапишет его.

До успешной регистрации старые локальные пароли не принимаются. После регистрации
хеш работает без постоянного соединения с backend; временная недоступность backend
не выключает уже настроенный доступ. Изменение ID/ключа/домена/хеша делает привязку
недействительной и требует регистрации заново. Не клонируйте готовые конфигурации
RustDesk с ID/приватным ключом между устройствами.

Клиент скрывает блок одноразового пароля и оставляет надпись
«Ваш рабочий стол доступен с этим ID». Это не означает доступ без аутентификации:
подключающемуся клиенту нужен индивидуальный пароль.

Операторская сборка — отдельный следующий этап: один вход с операторским паролем,
токен в защищённом хранилище ОС, автоматический запрос индивидуального пароля по ID.
API и подробный сценарий находятся в `../rustdesk-backend/OPERATOR_CLIENT.md`.
